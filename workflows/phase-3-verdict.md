## 步骤 1: 初判定级

### 判定矩阵

| 判定等级 | 触发条件 (满足任一) |
|----------|-------------------|
| 🔴 **高风险** | 综合分 ≥ 25 |
| 🔴 **高风险** | P0 ≥ 1 + 已实际转账 |
| 🟠 **中高风险** | 综合分 10-24 |
| 🟠 **中高风险** | P0 ≥ 1（但未实际转账） |
| 🟡 **中度疑虑** | 综合分 4-9 |
| 🟡 **中度疑虑** | P1 ≥ 2 + 操控手法 ≥ 3 |
| 🟢 **低风险** | 综合分 < 4 + 无 P0/P1 |
| ⚪ **数据不足** | 对方消息 < 10 条 + 关键信息缺失 |

### 特别升级规则

以下情况自动升级一级：
1. 用户年龄 50+ + P0 ≥ 1 → 自动升级为 🔴 高风险
2. 用户已有大额金钱损失 (>10000元) → 自动升级为 🔴 高风险
3. 用户表达自伤/自杀念头 → 暂停分析，触发 Phase 5 紧急危机响应

### 特别降级规则

以下情况可考虑降低一级：
1. 双方已有多次线下见面（而非仅网上聊天） → 降一级
2. 有第三方独立验证对方的身份信息 → 降一级
3. 用户和对方有共同的朋友/社交圈 → 降一级

## 步骤 2: 置信度计算

### 置信度 = 数据充分性 × 证据一致性

**数据充分性因子**:
| 条件 | 因子 |
|------|------|
| 对方消息 >30 条 + 时间跨度 >2周 | 1.0 |
| 对方消息 10-30 条 + 时间跨度 >1周 | 0.8 |
| 对方消息 <10 条 或 时间跨度 <1周 | 0.5 |

**证据一致性因子**:
| 条件 | 因子 |
|------|------|
| 所有红旗指向一致，无矛盾证据 | 1.0 |
| 大部分红旗指向一致，少量矛盾 | 0.8 |
| 红旗相互矛盾或模棱两可 | 0.5 |

**置信度百分比** = 数据因子 × 证据因子 × 100

## 步骤 3: 证据摘要

### 输出格式

```
## 综合判定结果

**判定等级**: [🔴/🟠/🟡/🟢/⚪] [等级名称]
**置信度**: 约 XX%

### 关键证据 (支持判定的主要依据)
1. **[证据标题]** → [对应的红旗/模式/操控手法]
   > "[从聊天记录中引用的原文]"
2. ...

### 减损因素 (指向相反方向的证据)
- [如果存在有利于对方的解释，在此列出]

### 分析局限性
1. 数据充分性: [充分/一般/不足]
2. 以下信息缺失: [列出]
3. 本分析无法确定: [列出]
4. AI 分析的性质: 这是基于模式的概率判断，不是事实认定
```

## 步骤 4: 面向用户的判定陈述

### 🔴 高风险模板
```
根据分析，有 [N] 个关键红旗指向这个关系存在问题。
这些红旗与 [诈骗类型名称] 的已知模式高度吻合。
我的判定是：🔴 高风险 — 这是一个高度疑似的情感诈骗。
接下来我会给你一些具体的应对建议。
```

### 🟠 中高风险模板
```
这次分析发现了几个值得高度关注的问题。
虽然没有到达"确定诈骗"的程度，但我建议你保持强烈警戒。
```

### 🟡 中度疑虑模板
```
有一些信号需要更多信息才能下结论。
目前的判断是 🟡 中度疑虑 — 不能排除风险，但也缺乏决定性证据。
我建议你先做几件事来验证对方...
```

### 🟢 低风险模板
```
从聊天记录来看，没有发现典型的诈骗红旗。
这个关系看起来是正常的交往。
以下是几点健康关系的建议...
```

### ⚪ 数据不足模板
```
目前聊天记录太少（仅 [X] 条），无法做出准确分析。
勉强给结论是不负责任的。
我建议你先继续聊天，收集更多信息后再来分析。
```
