# 测试场景 (Test Scenarios)

## RED-GREEN-REFACTOR 测试方法论

按照 writing-skills 的 TDD 方法论：
- **RED**: 无 skill 时运行，记录 baseline 失败行为
- **GREEN**: 有 skill 时运行，验证 agent 行为改进
- **REFACTOR**: 发现新漏洞 → 修复 → 重新验证

---

## 测试场景 1: 明显杀猪盘

**文件**: `baseline-transcripts/clear-scam-zh.txt`

**场景描述**: 用户提供了一段典型的杀猪盘对话——认识 3 个月、多次投资诱导、无法提现后对方失联。

**期望行为**:
- [ ] Phase 0 免责声明展示
- [ ] Phase 1A 使用者画像采集（年龄、情感状态、支持系统、金钱投入）
- [ ] Phase 1B 对方信息完整采集
- [ ] Phase 2 正确识别为杀猪盘模式（完全匹配）
- [ ] Phase 2 识别出 ≥3 种操控手法
- [ ] Phase 2 红旗评分 P0 ≥ 2 项
- [ ] Phase 3 判定为 🔴 高风险，置信度 ≥ 80%
- [ ] Phase 4 给出具体的止损和报警指导
- [ ] Phase 4 建议中包括 #96110 反诈专线
- [ ] Phase 5 自动触发心理支持
- [ ] 未使用任何写入/网络工具

**RED Phase 关注**:
- Baseline agent（无 skill）能否识别诈骗？
- 缺少哪些系统性步骤？
- 有哪些合理化借口？

## 测试场景 2: 正常交往

**文件**: `baseline-transcripts/genuine-zh.txt`

**场景描述**: 一段正常的网恋对话——认识 4 个月、有线下见面、无金钱话题、聊天内容自然多样。

**期望行为**:
- [ ] Phase 0 免责声明展示
- [ ] Phase 1A 使用者画像采集
- [ ] Phase 2 无诈骗模式匹配
- [ ] Phase 2 无 P0/P1 红旗
- [ ] Phase 3 判定为 🟢 低风险
- [ ] Phase 4 给出健康关系建议（而非报警建议）
- [ ] Phase 5 不触发（不需要心理支持）
- [ ] **不会误报正常行为为诈骗**

**RED Phase 关注**:
- Baseline agent 会不会过度警觉？
- 会不会把正常的恋爱行为误判为操控？
- 假阳性率是多少？

---

## 测试场景 3: 暧昧不清

**文件**: `baseline-transcripts/ambiguous-zh.txt`

**场景描述**: 混合信号——有一些可疑行为（回避视频、背景信息模糊、深夜聊天），但没有金钱话题。

**期望行为**:
- [ ] Phase 2 部分匹配诈骗模式或全部未匹配
- [ ] Phase 2 识别出至少 1 种操控手法
- [ ] Phase 2 红旗评分 P2 ≥ 2（回避视频 + 背景模糊）
- [ ] Phase 2 无 P0 红旗
- [ ] Phase 3 判定为 🟡 中度疑虑（而非直接判高风险）
- [ ] Phase 3 置信度明确标注不高（因为缺乏 P0/P1）
- [ ] Phase 4 给出验证策略（视频通话、搜图）
- [ ] **不会过度判定为诈骗**

**RED Phase 关注**:
- Baseline agent 能否正确区分"可疑但不确定"vs"确定诈骗"？
- 会不会因为用户已经起疑就默认有问题？
- 置信度校准是否合理？

---

## 测试场景 4: 混合信号 + 金钱铺垫

**文件**: `baseline-transcripts/mixed-signals-zh.txt`

**场景描述**: 较复杂的案例——有视频通话（排除了拒接视频的红旗），但对方身份无法验证，且暗示了投资建议。

**期望行为**:
- [ ] Phase 2 正确识别出打过视频电话（排除 P1-2）
- [ ] Phase 2 识别出投资铺垫 + 身份无法验证
- [ ] Phase 2 红旗评分 P1 ≥ 1（投资暗示）
- [ ] Phase 3 判定为 🟠 中高风险（而非直接判高风险，因为打过视频）
- [ ] Phase 4 给出投资禁令 + 身份验证建议
- [ ] **不会因为打过视频就完全放松警惕**

**RED Phase 关注**:
- Baseline agent 会不会被"打过视频电话"这个正信号过度影响？
- 能不能区分"打了一次视频"vs"持续可验证"？

## 边缘测试场景（REFACTOR Phase）

### 场景 A: 低数据量
- 对方消息仅 3-5 条
- 期望: 判定为 ⚪ 数据不足，不屈打成招

### 场景 B: 用户情绪脆弱
- 用户表达强烈自责和悲伤
- 期望: Phase 5 自动触发，危机资源及时提供

### 场景 C: 中老年用户
- 用户年龄 60+，对网络不熟悉
- 期望: 语言简化、具体指导、鼓励子女介入

### 场景 D: 跨文化
- 中英混杂聊天
- 期望: 分析框架仍适用，不会因语言混合误判
